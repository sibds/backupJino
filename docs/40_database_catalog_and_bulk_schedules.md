# Копии БД и групповые расписания в карточке сервера

## Список копий

Вкладка «Базы данных» начинается со списка копий. Для каждой БД показаны результат последней проверки, размер последней копии, местное время скачивания, дата исходного снимка и расписание с датой следующей постановки. Скачивание старого снимка не делает дату данных свежей. При наличии более нового известного снимка отображается отдельная подпись.

Сводный объём — сумма последних проверенных копий из справочника, без старых версий и незавершённых частей. Это указано рядом со списком; сумма не выдаётся за полный размер каталога на диске. Нулевой известный размер и неизвестный размер различаются. Неизвестные даты не заменяются временем задания. Названия остаются в приватном API карточки; публичные журналы и параметры заданий используют псевдонимы.

Поиск и фильтры позволяют оставить скачанные БД, базы без копии, копии с более новым известным снимком или БД с расписанием. «Выбрать видимые» относится к отфильтрованным строкам; число выбранных показывает весь выбор, включая скрытые фильтром строки. Выбор хранится отдельно для сервера и версии настроек, сохраняется при обновлении данных. Полная таблица серверов не перерабатывалась.

## Групповые действия

«Скачать выбранные» ставит одно БД-задание с выбранными `db_aliases`. Кнопка конкретной строки скачивает одну БД. Обе операции выбирают последний доступный существующий снимок Jino; новый снимок живой БД не создаётся. Пользователь подтвердил этот способ. Снимок с ручной датой и управление общим заданием находятся в раскрываемом блоке под списком.

Кнопка **«Скачать недостающие (N)»** рядом с обновлением списка одним нажатием ставит все известные БД сервера без проверенной копии (`validation != PASS`) в одно задание. Поиск, фильтр и выбор строк не ограничивают эту команду. Уже проверенные копии, включая старые снимки, пропускаются: обновление старой копии остаётся отдельным действием. При неполном справочнике сначала необходимо получить остальные названия из Jino. Кнопка недоступна при существующем активном БД-задании, заблокированном сервере, выполняющемся запросе или отсутствии недостающих копий. Это статическое расширение не требует перезапуска исполнителя.

Проверка этой кнопки: **22 JS-теста прошли**, Chrome на 1440/1000/800/390 подтвердил выбор недостающих БД за пределами текущего фильтра, исключение проверенных копий и отсутствие второго задания от двойного клика. Работающая панель отдаёт обновлённый JavaScript с `no-store`; загрузки не перезапускались. Синтетический тест не запускал выгрузку на реальном Jino.

«Настроить расписание» открывает общую форму для выбранных БД. Варианты: каждые 24 часа, каждые 72 часа, раз в неделю (168 часов) или целое число часов от 1 до 8760. Первое планирование назначается через выбранный интервал. «Применить» заменяет расписание только выбранных баз; «Выключить» отключает его без удаления копий. Настройка одной строки использует ту же форму с одной выбранной БД.

Расписания действуют при запущенном исполнителе. Показано время постановки, а не обещанное время завершения: общий допуск панели, одно БД-задание и CAPTCHA сохраняются. Повторная проверка или использование ранее проверенного дампа того же снимка сохраняют исходное время скачивания.

## Контракт API и идемпотентность

Существующий `POST /api/servers/{row}/database-schedules` принимает прежний `db_alias` или новый непустой список `db_aliases` (не более 500). Одновременная передача обоих полей отклоняется. `enabled` — boolean, `every_hours` — целое число 1–8760. Привязка всех псевдонимов проверяется по серверу и текущей версии; неизвестный псевдоним отклоняет всю операцию. Зашифрованные payload обновляются одной транзакцией SQLite. Ответ дополнен `updated_count` и `next_at`.

Одинаково назначенные БД с совпадающими интервалом и временем следующей постановки объединяются в одно задание, чтобы использовать один панельный вход. Для группы сохраняется стабильный `schedule_occurrence` из отсортированных псевдонимов и даты; для одиночной БД прежний формат сохранён. Продвижение всей группы на следующий интервал выполняется одной транзакцией. Восстановление между сохранением задания и продвижением расписаний использует прежнее задание, а не создаёт повторное. Само по себе изменение интерфейса не включает расписания реальных клиентов.

## Проверки

Полный прогон: **362 passed, 1 skipped**, 69,80 с; после дополнительного сценария восстановления групп прошли семь целевых тестов. JS: **21 passed**. Chrome на искусственном сервере проверил ширины 1440/1000/800/390, 72/168-часовые интервалы, выключение, выбор и черновик после обновления, фильтры, новый снимок при недавнем скачивании старого, длинное имя, неизвестные данные, нулевой размер, пустой список, ошибку сохранения и недоступную повторную выгрузку при существующем задании. Отдельный браузерный прогон подтвердил сохранение таблицы серверов, графиков и навигации.

Визуальные доказательства: `.impeccable/review/database-card-*.png`, `database-schedule-*.png`, `database-error-1440.png`, `database-busy-390.png`, `database-empty-390.png`. Данные и операции синтетические, обращения к Jino в этих проверках блокировались. Тест нулевого размера проверяет отображение граничных метаданных, а не допустимость пустого SQL в валидаторе.

Независимый finish reviewer вынес **ship** по девяти переданным снимкам и коду интерфейса, без material fixes; область вывода — проверенное расширение вкладки БД, не интеграция с Jino. Документер подтвердил сохранение существующей визуальной системы; отчёты — `.impeccable/review/database-catalog-review.md` и `database-catalog-documentation.md`. Предсуществующие рассинхрон sidecar и отсутствие buildPath не исправлялись в этой задаче.

## Установка

Протокол `.state/database-catalog-deployment.json`, фаза `RESTORED`: пять прежних активных FTPS-заданий продолжены, 23 ожидающих восстановлены, сохранены все 28 ID, новые ключи не создавались. Перед остановкой подтверждено отсутствие выполняющегося БД-задания. Части и копии сохранены. Самостоятельно расписания клиентов не включались.

После установки выполнена read-only проверка Chrome на 1440/390: вкладка показала 43 записи БД из сохранённого справочника, выбор и форма периодичности доступны, переполнения и ошибок JavaScript нет. Отправлялись только локальные GET; запросов в Jino, операций расписания и снимков клиентских данных не выполнялось. Это подтверждает отображение установленной версии, не новый живой экспорт.
