# Общий прогресс сервера в таблице

12 ноября 2026 года пользователь уточнил: строка сервера должна показывать совокупный прогресс файлов и БД. Прежний `renderTable` использовал `current(server).percent`, то есть процент одного текущего файла. Это исправлено в статических ресурсах интерфейса без перезапуска работающих выгрузок.

## Расчёт

`serverWorkProgress` использует последние управляемые задания `files` и `databases` данного сервера:

- Файлы: подтверждённые `received_bytes / planned_bytes` всего дерева, когда `inventory_complete` подтверждён.
- БД: `verified_count / expected_count` всех дампов задания.
- Если есть оба задания, их доли имеют равный вес. Например, FTP 40% и БД 2/4 дают общий показатель **45%**. Размеры файлов и количество БД не складываются в одну физическую единицу.
- Если есть только одно задание, учитывается оно. Пока общий объём или состав дампов неизвестен, точного общего процента нет. Сохранённые байты и отдельные подписи FTP/БД остаются видны.
- Новое задание в очереди даёт нулевой вклад. Уже сохранённый прогресс при ожидании продолжения не обнуляется.
- 100% возможно после подтверждённого успешного результата задания. До финальной проверки вклад незавершённого задания ограничен 99%; `PARTIAL` не получает 100%.

При отсутствии управляемых заданий доступны сохранённые сводные сведения прежнего прохода. Процент отдельного файла при этом также не используется. Если данных нет, полоса не придумывается.

Это показатель выполнения последних заданий, а не статус полноты бэкапа. `FILES_ONLY`, `DB_ONLY`, `PARTIAL`, ошибки, дата снимка и отсутствие теста восстановления сохраняют своё значение.

## Отображение

Колонка переименована в **«Прогресс сервера»**. Она содержит сохранённый объём, общую полосу и подписи, например `FTP: 40% · БД: 2/4`. Подсказка поясняет равный вес заданий. Доступное имя — «Общий прогресс заданий сервера», `aria-valuetext` включает общий и составные результаты.

При неизвестном общем объёме работающее задание имеет неопределённый индикатор и текст «Прогресс уточняется». Завершённый частичный результат имеет текст «Частичный результат» без движущейся полосы. На телефоне прогресс занимает всю ширину строки перед кнопками управления; прежнее скрытие этой колонки отменено.

Прогресс отдельных файлов сохранён в подробностях и карточке сервера. API, исполнитель, очередь, ключи копий и соединения не изменены.

## Проверки

- Сначала воспроизведено отсутствие расчёта общего прогресса отдельным тестом.
- Затронутые тесты панели: **14 passed**, 7,22 с; проверены FTP+БД, один тип задания, неизвестный объём, новая очередь, ожидание продолжения с сохранёнными дампами, завершающая проверка, успешный и частичный результаты. Команда: `.venv/Scripts/python.exe -m pytest -q tests/test_dashboard.py --basetemp .test-tmp/server-progress-validation`. Это не новый полный прогон всего проекта.
- Синтетический Chrome на 1440/390 px подтвердил общий показатель 45% при текущем файле 99%, отдельную БД 50%, завершённые задания 100%, неизвестное состояние и `PARTIAL`. Общая полоса видна на обеих ширинах, ошибок JavaScript и горизонтального переполнения нет.
- Работающая локальная панель проверена только чтением на 1440/390 px. В строках используются новые общие индикаторы, подпись процента отдельного файла отсутствует. Ошибок JavaScript и изменяющих HTTP-запросов нет, PID исполнителя сохранился. Клиентские снимки экрана не создавались.
- Узкий финальный UI-review вернул `ship`; синтаксис JS и `git diff --check` проверены. Новые цвета или компоненты не вводились.
