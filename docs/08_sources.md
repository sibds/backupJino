# Источники и проверенные ограничения

Сводка обновлена 12 ноября 2026 года. Ссылки ниже — источники исходного исследования; текущая актуализация документации сверяла локальный код и сохранённые отчёты, без новых входов в клиентские аккаунты и без новой проверки всех внешних страниц.

## Официальная документация Jino

1. [Хостинг, файлы, MySQL, SSH, резервные копии](https://jino.ru/spravka/hosting/) — подтверждает поддержку FTP/SFTP/FTPS, ручные резервные копии и получение данных из `backups/`.
2. [Как сохранить бэкап на своём компьютере](https://o.jino.ru/help/faq/filemanagement/save-backup-on-computer/) — описывает упаковку в `.tar.gz` и загрузку по FTP.
3. [FTP-доступ и безопасные протоколы](https://o.jino.ru/help/faq/ftp/) — рекомендует FTPS/SFTP и описывает ограничения доступа.
4. [Удалённое подключение MySQL](https://jino.ru/landing/help/faq/mysql-general/connection-to-base/) — по умолчанию внешние подключения закрыты; разрешение по IP задаётся через панель.
5. [Экспорт/импорт через phpMyAdmin](https://o.jino.ru/help/faq/phpmyadmin/) — штатные инструменты выгрузки SQL.

## Исходные материалы проекта

- `money.py` — исторический скрипт работы с авторизацией Jino и стоимостью услуг; не API резервных копий.
- `sites (9).xml` — экспорт профилей FileZilla, 43 подключения с сохранёнными паролями в base64; не включать значения секретов в документацию.
- `abw_sibds__server.json` — полученный JSON-дамп таблицы MySQL с доступами к панели; структура исследована локально 10 ноября 2026 года: 56 записей, 24 поля. Значения не публиковались.
- `sites.xml` — фактически полученный экспорт; строгий XML-разбор не пройден (строка 126, столбец 44). Исторические количества для `sites (9).xml` к нему автоматически не переносятся.

## Статус утверждений

**Подтверждено по документации:** наличие стандартных механизмов резервных копий, путь выгрузки в `backups/`, экспорт SQL, поддержка FTPS/SFTP и ограничения внешнего MySQL.

**Исторические сведения SDD:** описание операций `money.py`, 43 FileZilla-профиля и base64-кодирование их паролей. Указанные исторические файлы отсутствуют и повторно не проверялись.

**Подтверждено текущим локальным исследованием:** схема JSON и ошибка разбора `sites.xml`; см. [отчёт](09_local_validation.md).

**Подтверждено согласованным живым пилотом:** вход в один аккаунт, появление нового MySQL-снимка после единственного запроса и форма экспорта SQL с явным назначением `/backups/…`. Файловый проход по 54 профилям завершился отказами, файлов не получено. Полные результаты: [массовое скачивание и панельный пилот](10_download_and_panel_pilot.md).

**Дополнительно подтверждено приложением 10 ноября 2026 года:** экспорт всех 3 БД существующего снимка через панель, ожидание SQL в `/backups/дата`, скачивание штатным HTTPS-файловым менеджером с проверкой TLS, проверка размера/структуры/хеша и повторный запуск без новых экспортов. [Журнал сквозного теста](11_database_export_integration.md). Публичные модули текущего UI исследованы локально; это наблюдаемый контракт, не гарантия стабильности API.

**Дополнительно подтверждено 11 ноября 2026 года:** актуальная справка Jino указывает явный FTPS21 и SFTP2222. После замены системного CA-хранилища на certifi FTPS-адаптер приложения успешно выполнил вход, список каталогов и чтение небольшого файла на трёх предоставленных профилях. Сверены локальные настройки и публичный сертификат FileZilla без извлечения паролей. [Исследование цепочки доверия и протоколов](16_ftps_protocol_diagnostics.md).

**Дополнительно подтверждено массовым проходом 11 ноября:** 7 результатов `DB_ONLY`, 47 `FAILED`, 53 проверенных SQL и 1 035 проверенных файлов; 34 аккаунта требуют CAPTCHA. [Итоги и ограничения](13_all_accounts_download.md). Это результат конкретного прохода, а не текущая доступность всех серверов.

**Дополнительно подтверждено 12 ноября:** параллельный FTPS, общий ограничитель сеансов и восстановление после прерываний проверены синтетически; на живом задании зафиксирован libcurl 18 (`RETR`, передача короче ожидаемой), сохранение части и автоматическое продолжение. [Передача](22_parallel_ftps.md), [обрыв и докачка](24_large_file_recovery.md). Официальная [таблица libcurl](https://curl.se/libcurl/c/libcurl-errors.html) подтверждает смысл кода, но не определяет виновника закрытия соединения.

**Не подтверждено для всего реестра:** пригодность всех панельных доступов, привязки конкретных сайтов и полного состава их БД, завершение всех живых файловых копий. Реальное MFA, автоматическое создание снимка приложением, восстановление приложения и стабильное публичное API бэкапов Jino также не подтверждены; соответствующие запланированные функции нельзя считать реализованными.
