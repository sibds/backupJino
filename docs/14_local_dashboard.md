# Локальная панель прогресса

В этом документе зафиксирован первый выпуск панели. Управление заданиями и серверами, карточки, план, приоритеты и общий лимит входов добавлены в [следующей доработке](15_management_and_work_plan.md).

11 ноября 2026 года пользователь выбрал просмотр только на текущем компьютере. Добавлена команда `backupctl ui`. Панель открывается в браузере по адресу `http://127.0.0.1:8765/` и слушает только loopback-интерфейс.

## Запуск

Из папки проекта выполните команду.

Сокращённый запуск ниже предназначен для уже настроенной рабочей папки с метаданными предыдущего прохода. При первом запуске нужны явные `--destination` и `--batch-id`, иначе возникает `DASHBOARD_BATCH_REQUIRED`. [Полная установка и команда первого запуска](../README.md#быстрый-запуск-панели). Текущая панель хранит управляемую очередь отдельно в SQLite; история прежнего массового прохода остаётся дополнительным источником данных.

```powershell
.venv\Scripts\backupctl.exe ui --open
```

Для текущего массового прохода назначение, ключ запуска и путь журнала берутся из `.state/active-download.json`. Параметры можно указать явно.

```powershell
.venv\Scripts\backupctl.exe ui --file abw_sibds__server.json --mapping examples/jino-mapping.json --destination F:\jino --batch-id all-available-2026-11-11 --port 8765 --open
```

Метаданные процесса панели сохраняются в `.state/dashboard-server.json`. После остановки панели команда запускает её повторно. После смены массового прохода панель требуется перезапустить, чтобы прочитать новые метаданные исполнителя. Автозапуск при входе в Windows пока не настроен.

## Что показывает экран

- Имена и логины исходных записей, поиск по ним, фильтры очереди и проблемных результатов.
- Живой процесс выгрузки, текущий этап аккаунта, сохранённые байты, число проверенных файлов и дампов.
- Размер и процент текущего обычного файла, когда размер известен. Общий размер дерева заранее неизвестен.
- Количество проверенных SQL и исходную дату снимка. Для текущего SQL до проверки доступно число сохранённых байт. Полный размер в этом случае обозначается как уточняемый.
- Папку сервера по логину и копирование пути в буфер обмена.
- Последние обезличенные события и сообщения об ошибках.

Прогресс обновляется каждые три секунды, пока вкладка видима и включено автообновление. Сохранённые части и проверенные артефакты учитываются раздельно. Итоговые `DB_ONLY`, `FILES_ONLY`, `PARTIAL` и `FAILED` сохраняют своё значение. Дата загрузки отдельно от даты снимка. Остановка исполнителя отображается как остановка задания, доступность сервера в этом случае оценивается по последней проверке.

## Проверка доступности

Кнопка «Проверить доступ» вверху ставит проверки однозначных аккаунтов в последовательную очередь. Та же кнопка в подробностях проверяет один выбранный аккаунт. Проверка выполняет штатный вход и чтение списка файлов через панель. Для активной выгрузки используются уже имеющиеся сведения текущего задания. В доработке управления проверки используют общий с заданиями панели часовой допуск и уступают ожидающим резервным заданиям. [Актуальные ограничения и CAPTCHA](15_management_and_work_plan.md#ограничение-входов-и-captcha).

Отдельные проверки выполняются по запросу оператора. Между повторными проверками аккаунта выдерживается минута. Открытие страницы само по себе читает локальный прогресс. Непроверенные аккаунты обозначены явно, неоднозначные строки 1 и 53 требуют проверки исходной привязки. MFA, CAPTCHA и изменения UI отражаются как требующие действия оператора.

Доступность здесь означает возможность авторизации и чтения файлов для резервного копирования. Проверка HTTP-работоспособности клиентских сайтов пока отсутствует.

## Чтение работающей выгрузки

Windows может отклонить атомарную замену файла, пока другой процесс держит его открытым. Это воспроизведено локально, включая чтение с разрешением совместного удаления. Поэтому панель получает текущие этапы из дописываемого JSONL-вывода исполнителя, SQL-события из `panel_jobs/*.events.jsonl`, файловые checkpoint из SQLite в режиме `mode=ro`, размер SQL-частей через метаданные файлов.

Живой `jino-all-*.json` и заменяемые зашифрованные журналы `.enc` во время опроса содержимого не открываются. Статистика файла отчёта читается через `stat`. SQLite-соединения закрываются сразу после запросов с коротким тайм-аутом. Панель работает отдельным процессом. Её закрытие оставляет текущую выгрузку работающей.

Путь дописываемого stdout-журнала должен находиться внутри каталога состояния и быть указан в `active-download.json`. Для текущего скрытого запуска он настроен. При отсутствии пригодного журнала панель показывает отсутствие данных. Для другого способа запуска требуется соответствующий журнал и метаданные процесса.

## Данные и HTTP

Имена, логины, относительные имена файлов и пути сохранения показываются локальному оператору. Пароли, cookies панели Jino, токены файлового транспорта, имена БД, SQL и ключи шифрования исключены из ответа API. Проверки сохраняют только фиксированные статусы и обезличенные ошибки в `dashboard-health.json`.

Локальный HTTP-сервер выдаёт фиксированный набор статических ресурсов. `GET /api/state` требует сессионную HttpOnly cookie с `SameSite=Strict`. `POST /api/checks` дополнительно проверяет локальный Origin. Проверяется Host, сторонние имена и произвольные пути отклоняются. Внешние шрифты, аналитика и CDN отсутствуют. Журналы HTTP-запросов отключены. Браузерная сессия получает доступ к локальным именам и путям, поэтому экран и его снимки следует хранить как клиентские данные.

## Проверки

Синтетические тесты покрывают сокрытие секретов, чтение checkpoint без изменения, остановку исполнителя, отсутствие ложного подтверждения доступа, повреждённый и усечённый журнал, пропуск активных и неоднозначных аккаунтов, запрет чтения заменяемого отчёта, справку CLI, ограничения HTTP.

Браузерная проверка выполнена в установленном Chrome на искусственных данных при ширинах 1440, 390, 800 и 1000 пикселей. Проверены поиск, пустое состояние, фильтры, выбранный сервер, SQL с неизвестным полным размером, исходная дата снимка, журнал, ручная проверка доступа и копирование пути. На промежуточных ширинах проверены доступные имена и клавиатурный фокус сокращённых кнопок. Ошибок JavaScript и горизонтального переполнения документа не обнаружено. Независимый визуальный review выявил отсутствие постоянных доступных имён сокращённых кнопок. Исправление проверено повторно, reviewer вернул `ship` для этого исправления.

Два последовательных полных прогона pytest после исправлений завершились с результатом **191 passed, 1 skipped**, 31,63 и 28,67 с. Пропущен необязательный нативный MySQL-тест.

В предыдущих прогонах периодически возникал `PermissionError` при замене локального состояния. Сбой затрагивал разные синтетические сценарии экспорта и восстановления журнала. Повтор вне песочницы подтвердил `WinError 5` непосредственно в `os.replace` при обновлении отчёта. Для атомарной записи JSON, зашифрованного журнала и фиксации SQL добавлен общий ограниченный повтор замены. Для кодов Windows 5, 32 и 33 допускаются шесть попыток с суммарной задержкой 0,62 с. Прочие ошибки передаются сразу. После исчерпания попыток ошибка сохраняется. Повтор замены локального файла выполняется отдельно от отправки панельной операции. Конкретный процесс, создававший кратковременную блокировку, не установлен.

Семь регрессионных проверок моделируют временную блокировку, постоянный отказ и вызовы записи JSON и приватного состояния. Дополнительно проверено время подтверждения доступа именно выбранного аккаунта, чтобы интерфейс показывал время его события входа.

Живой HTTP-запрос к запущенной панели получил `200` и актуальную сводку завершившейся очереди. Статусы и числа совпали с итоговым отчётом, прочитанным после окончания записи. Ошибок в stderr панели на момент проверки нет. Результаты браузерных сценариев относятся к искусственным данным, доступность реальных аккаунтов отражена результатами массового прохода.
