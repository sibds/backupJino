# Изменения источника во время длительной загрузки

Уточнение оператора: управляемая панель спрашивает, какой различающийся вариант сохранить, вместо автоматической замены собственной копии. Актуальные действия — [52](52_operator_decisions_and_versions.md).

По указанию оператора от 16 ноября изменение отдельного файла или дочернего каталога не должно останавливать управляемую файловую копию. Ключ, каталог копии и пригодные части сохраняются. Это дополнение к [50](50_download_until_complete.md) и [41](41_file_conflicts_and_scoped_errors.md).

## Обработка

- FTPS при `SOURCE_CHANGED` повторно читает метаданные файла, обновляет его запись в постоянном журнале обхода и пытается скачать актуальную версию. В одном проходе — до трёх попыток, после чего остальные файлы продолжаются. Готовая копия с изменившимся источником проходит тот же механизм обновления.
- Проверенная локальная версия того же серверного пути автоматически заменяется после скачивания и проверки кандидата, даже если дата источника не стала новее. Старые байты сохраняются в `.jino-progress/preserved`. Чужой файл, локальные правки и разные серверные пути не получают такого разрешения и остаются отдельными конфликтами с выбором оператора.
- Изменившийся дочерний каталог перепроверяется, его устаревший кэш и кэш родителя сбрасываются. При повторяющейся ошибке он остаётся в предупреждениях, остальные каталоги продолжаются.
- Неоднозначное имя в ответе `MLST` больше не принимается за доказанное изменение файла. Ответ отбрасывается, используется строгий `MLSD` запрошенного родителя с прежними проверками корня и имени. Путь, присланный в неоднозначном ответе, не используется для скачивания.
- SFTP и HTTPS-файлы используют обновление метаданных в последовательном сборщике; для управляемого HTTPS включено сохранение проверенного старого файла перед обновлением. CLI остаётся строгим по умолчанию.

Если проход остаётся `PARTIAL` с `source_changed_count > 0`, то же задание возвращается в `SCHEDULED / SOURCE_REFRESH_WAIT` через 5/15/30/60 минут. Подтверждённый рост байтов сбрасывает задержку. Общего срока нет. Это не новый запуск по расписанию и не новая версия. Для незавершённого FTPS-прохода сохраняются квитанции проверенных файлов, чтобы повтор не начинал все локальные проверки заново.

## Границы

Ручные паузы и остановки сохраняются. Привязка, TLS, допустимый корень, типы объектов, безопасные пути и лимиты остаются обязательными. Изменение канонического корня при переподключении — `DOWNLOAD_SCOPE_CHANGED`, а не локальный `SOURCE_CHANGED`, и требует решения оператора. Ошибка исходной привязки аккаунта также не становится разрешением повторять чужую выгрузку.

Файлы сайта живые, поэтому результат остаётся `BEST_EFFORT`: это не атомарный снимок. Неустранённые изменения сохраняют `PARTIAL`; дата скачивания не подменяет дату источника. Одинаковые размер и время не доказывают одинаковое содержимое, FTP не даёт гарантии обнаружения изменения без изменения доступных метаданных.
