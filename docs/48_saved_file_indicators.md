# Сохранённые файлы и новый запуск

После постановки нового задания панель показывала только его показатели. Нулевой или маленький прогресс подменял в интерфейсе объём предыдущего запуска, хотя прежняя папка оставалась на диске. Дополнительно при разделении проверки из сводки карточки исчез счётчик сохранённых файлов — вместо него оставался только текущий `processed_files`.

Теперь отдельно видны:

- сохранённые файлы и объём текущего запуска;
- текущая проверка: N из M и остаток очереди;
- последний предыдущий запуск с ненулевыми сохранёнными показателями.

В таблице «Серверы», правом блоке, сводке карточки и вкладке файлов добавлены прежние показатели. Пока новый запуск пустой, сводка явно подписывает значения как «Ранее сохранено файлов» и «Объём предыдущей копии». После появления данных нового запуска оба запуска показаны раздельно. Их объёмы не складываются, прежний не выдаётся за результат текущей выгрузки. Данные иной `revision` не присваиваются новой привязке. Неудачный прошлый запуск также может содержать сохранённые файлы; его показатели не означают завершённый бэкап.

Изменён только статический интерфейс. API, исполнитель, расписания, части и ключи не менялись. Для обновления достаточно перезагрузить страницу.

## Фактическая проверка

В истории `sibdsgos`, `sibds2`, `sibds7` обнаружены соответственно около 70,91 / 33,77 / 3,70 ГБ подтверждённых записанных данных, включая части. Папки найдены; выборочно проверены девять готовых файлов по размеру и SHA-256, совпадение подтверждено. Это не полный повтор проверки всех артефактов. Исходные ID заданий сохранены.

## Регрессии

**31 JS-тест**, в том числе пустое новое задание с прежней копией, отличие числа сохранённых файлов от текущей проверки, независимые показатели растущей новой и прежней копий, защита привязки. **14 тестов панели**. `scripts/check_file_verification_ui.py` на синтетических данных проверяет таблицу, правый блок и обе вкладки карточки при 1440/1000/800/390; только GET, без реальных аккаунтов и изменения очереди.
