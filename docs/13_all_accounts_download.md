# Массовая выгрузка доступных серверов

Пользователь 11 ноября 2026 года по времени Омска поручил выгрузить все доступные серверы из предоставленного JSON. Прежний выбор сохранён: обычные файлы в `F:\jino`, папки серверов по логинам, без удаления существующих копий и серверных SQL.

## Объём и состояние запуска

В таблице 56 записей. Для 54 импортёр нашёл однозначные панельные доступы. Строки 1 и 53 имеют повторяющийся логин и остаются `ACCOUNT_AMBIGUOUS`; подбор или угадывание привязок не выполняется. Файловые аккаунты отделены от панельных: источник HTTPS привязывается к выбранному контейнеру через `objectId` штатного запроса.

Проход завершил обработку очереди 11 ноября. Ниже сохранён журнал промежуточных наблюдений и добавлен итог. Одновременно обрабатывались два аккаунта. Для каждого программа авторизуется, проверяет файловый источник, выбирает самый новый доступный MySQL-снимок, получает дампы его БД, затем скачивает доступное дерево обычных файлов. Ошибка одного аккаунта записывается отдельно.

Первоначальный проход начат 10 ноября в 18:42:27 UTC. После исправления ожидания промежуточного SQL процесс перезапущен с тем же ключом; текущий отдельный скрытый процесс начат **18:56:03 UTC** (11 ноября 00:56 по Омску), PID при запуске **10376**. Он работает независимо от окна диалога.

Текущее состояние и контрольные данные:

Отчёт обновляется во время работы. `finished: false` означает, что очередь ещё обрабатывается. Серверы имеют состояния `QUEUED`, `RUNNING` и итоговое состояние. Поля `stage`, `files_seen`, `bytes_saved`, `database_status` показывают ход работы. `bytes_saved` включает подтверждённые части незаконченных файлов и не является признаком полной копии сервера.

В первых двух аккаунтах обнаружены отдельные обычные файлы размером **15 911 060 572** и **23 690 090 637** байт. Они входят в запрошенное полное дерево и не исключаются автоматически. Передача длительная; остальные аккаунты ожидают свободного исполнителя. Точный общий срок до обследования остальных аккаунтов не установлен.

## Команда запуска и продолжения

```powershell
.venv\Scripts\backupctl.exe backup download-accounts --file abw_sibds__server.json --mapping examples/jino-mapping.json --destination F:\jino --batch-id all-available-2026-11-11 --workers 2 --execute --plaintext
```

Без `--execute` выполняется только локальная проверка списка, без инициализации, записи или сетевых действий. `--inspect-only --execute` проверяет доступ и даты снимков без экспорта и скачивания дерева. `--workers` допускает 1 или 2 аккаунта. Повтор той же команды с тем же ключом использует сохранённые задания и checkpoints; параллельный запуск того же batch блокируется.

Файловая копия находится в `F:\jino\<логин>\download-<ID>\files`, SQL — в `F:\jino\<логин>\panel-job-<ID>\databases`. Существующие папки и предыдущие копии не удаляются. Автозапуск после перезагрузки Windows не настраивался; после неё требуется повтор команды.

## Даты и границы полноты

Используется самый новый **доступный существующий** MySQL-снимок, а не автоматически созданный новый снимок. Его дата сохраняется отдельно от времени скачивания. На первом аккаунте повторно проверены ранее полученные 3 БД снимка `2026-11-10`; новые экспорты для них не отправлялись. На втором проверенном аккаунте самый новый снимок датирован `2026-11-08`; он отмечается `snapshot_stale: true`.

Ранее завершённая выгрузка БД повторно используется только после совпадения аккаунта, контейнера/снимка, полного состава БД и проверки локальных размеров, SHA-256 и структуры SQL. Отсутствие снимка или отказ БД не запрещают копирование доступных файлов.

Файлы копируются из живого дерева; согласованность обозначена `BEST_EFFORT`. Данные аккаунта не выдаются за подтверждённую полную копию каждого клиентского сайта. `backup_complete: false` и `application_restore_tested: false` сохраняются явно. При наличии файлов и дампов родительский результат остаётся `PARTIAL`; устаревший снимок не выдаётся за свежий. Поля `files` и `databases` содержат отдельные результаты.

## Передача и обработка перебоев

FTPS ранее не прошёл проверку на всех 54 профилях. Новый проход использует штатный HTTPS-файловый менеджер Jino с обычной проверкой сертификата, токеном в заголовке и запретом перенаправлений. Пароли, cookies, токены, имена БД и содержимое файлов в публичные отчёты не попадают.

Файлы сохраняются с `DirectoryCheckpoint`: подтверждённый префикс фиксируется с SHA-256 и синхронизацией на диск. При продолжении проверяются метаданные источника и локальный префикс. Для HTTP Range проверяется `Content-Range`. Если сервер игнорирует Range, программа читает и сравнивает удалённый префикс до дописывания остатка; это требует повторной передачи префикса, но не перезаписи готовых данных.

Отказ чтения отдельного обычного файла записывается в `files.errors` манифеста; остальные доступные файлы продолжают скачиваться. Такой результат `PARTIAL`. Лимиты размера, числа объектов, времени, свободного места и запреты небезопасных путей остаются останавливающими условиями. Ссылки не обходятся: их метаданные записываются в манифест, а содержимое по ссылкам не скачивается.

При сетевых сбоях предусмотрены ограниченные повторы. Истёкший токен файлового транспорта обновляется один раз; повторный отказ приводит к переподключению аккаунта с прежними заданиями. Для временных ошибок аккаунта допускаются до трёх попыток; неверный пароль, MFA или CAPTCHA автоматически повторяться/обходиться не должны.

## Итог обработки очереди

Общий отчёт прочитан после окончания записи, `finished` подтверждён как `true`. Обработаны 54 однозначных аккаунта, ещё две исходные записи требуют проверки привязки. Итоговые состояния аккаунтов содержат 7 `DB_ONLY` и 47 `FAILED`. Подтверждённой полной копии сервера этот проход не дал.

По локальным checkpoint и журналам проверки артефактов получены 1 035 проверенных обычных файлов и 53 проверенных SQL. Сумма сохранённых байт, включая подтверждённые части незаконченных файлов, составляет 77 339 501 186. Эта сумма включает частичные данные.

Распределение основной ошибки аккаунта следующее.

| Причина | Число аккаунтов |
| --- | --- |
| Хостинг потребовал CAPTCHA | 34 |
| Ошибка ответа панели | 7 |
| Тайм-аут браузерной операции, учтённый как `INTERNAL_ERROR` | 9 |
| Отклонён небезопасный удалённый путь | 2 |
| Хостинг отклонил вход | 2 |

Повторные входы для аккаунтов с CAPTCHA автоматически не запускаются. Для продолжения требуется штатное подтверждение оператора. Причины тайм-аутов и ответов панели требуют отдельной диагностики. Привязки небезопасных путей автоматически не расширяются. Повторный массовый проход после завершения этой очереди не запускался.

Состояния, имена и логины доступны оператору в [локальной панели](14_local_dashboard.md). Файлы, SQL и сохранённые части предыдущих попыток остались на месте.
