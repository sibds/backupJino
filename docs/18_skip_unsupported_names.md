# Пропуск имён, несовместимых с Windows

11 ноября 2026 года пользователь разрешил пропускать неподдерживаемые имена файлов и каталогов при обязательном отражении в журналах. Ранее [диагностика](17_remote_name_diagnostic.md) установила отказ на имени каталога с двоеточием. Реализован отдельный режим пропуска, без переименования исходных объектов.

## Настройка оператора

В карточке сервера, вкладка «Файлы FTP», перед кнопками запуска находится переключатель **«Пропускать имена, несовместимые с Windows»**. Для управляемой очереди он включён по умолчанию. Значение сохраняется отдельно для каждого сервера в локальном каталоге, исходный JSON не меняется. Имя настройки — `skip_unsupported_names`, тип — boolean.

Настройка применяется к файловым заданиям FTPS, SFTP и HTTPS. Запуск из строки таблицы или плана использует то же значение сервера. В новом задании политика фиксируется; продолжение остановленного, ошибочного или прерванного задания подхватывает текущую настройку. Менять её во время активной, приостановленной или запланированной работы сервера нельзя. Для ручного изменения следует сначала остановить работу. Привязка подключения и ключ существующего задания при смене этой настройки сохраняются.

Самостоятельные CLI-команды и обычный архивный workflow сохраняют прежний строгий режим. Для внутренних файловых workflow добавлен необязательный параметр `skip_unsupported_names=False`; новый обязательный аргумент CLI не вводился.

## Что пропускается

| Случай | Поведение при включённой настройке |
| --- | --- |
| Двоеточие, `?`, `*`, кавычка, `<`, `>`, `\|` в имени | Пропуск объекта с причиной `WINDOWS_CHARACTERS` |
| Точка или пробел в конце имени | Пропуск, `TRAILING_DOT_OR_SPACE` |
| Зарезервированное имя Windows, например `NUL.txt` | Пропуск, `WINDOWS_RESERVED_NAME` |
| Каталог с таким именем | Пропускается сам каталог и всё поддерево; обход внутрь не выполняется |
| `.`/`..`, разделитель внутри имени, управляющий символ | Остановка `REMOTE_PATH_UNSAFE`, независимо от настройки |
| Фактический выход за корень либо небезопасный токен HTTPS | Остановка; пропуск не ослабляет эту проверку |

Файлы с допустимыми именами продолжают скачиваться и проверяться обычным способом. Размер и количество объектов внутри пропущенного каталога неизвестны, поскольку приложение в него не входит. Процент передачи относится к подсчитанным поддерживаемым объектам; пропуски отдельно делают результат частичным.

Режим применяется к перечисленным проверкам совместимости имени. Он не является обещанием обработки всех возможных ограничений Windows, например любой предельной длины полного пути или проблем локального диска. Ошибки соединения и прав доступа сохраняют прежнюю обработку.

## Журнал и манифест

Предварительный обход пишет событие `FILE_SKIPPED` для каждого обнаруженного пропуска. В приватном журнале сервера сохраняются относительный путь, тип объекта, причина, время, идентификатор задания и счётчик пропусков. Код — `REMOTE_NAME_UNSUPPORTED`. Для каталогов интерфейс прямо указывает, что пропущено содержимое. Клиентские пути не добавляются в публичный отчёт массового запуска.

На вкладке «Журнал сервера» появился фильтр **«Пропуски имён»**. Он выбирает события этого типа до применения ограничения 500 записей: последующие события передачи не вытесняют пропуски из этого представления. Для запроса добавлен индекс событий по серверу и типу. Общий журнал также сохраняет прежние записи; в SQLite остаются все события.

При завершении задания пропуски записываются в `manifest.json`, в `files.skipped`. Каждый объект содержит `path`, `kind`, `reason`, `error_code`. Эти же пропуски включены в `files.errors`, чтобы потребитель прежнего формата не принял неполное дерево за полное. Внешний результат содержит `files_skipped_count`; `file_errors_count` включает все пропуски и другие ошибки. В карточке эти количества разделены.

При любом пропуске статус файлового результата — **`PARTIAL`**. Даже если поддерживаемых файлов не осталось, это частичный результат с нулём файлов, а не успешный `FILES_ONLY` или `COMPLETE`. При остановке/ошибке до создания нового манифеста уже обнаруженные пропуски остаются в журнале. Сохранённые копии и подтверждённые части не удаляются.

## Контракты локальной панели

`POST /api/servers/{row}` принимает `skip_unsupported_names: true|false`; строковые и числовые подстановки отвергаются. `GET /api/state` и карточка возвращают значение в `configuration`. Задание содержит зафиксированную политику и `progress.skipped_count`. `GET /api/servers/{row}` дополнительно возвращает `skipped_events` — до 500 последних событий пропусков выбранного сервера. Доступ остаётся локальным и требует прежней сессии.

## Проверки

Добавлены синтетические проверки копирования допустимого файла при неподдерживаемом соседнем файле/каталоге, запрета обхода пропущенного поддерева, строгого режима, неподдерживаемого целиком дерева, сохранения политики и её применения при продолжении, записи событий/манифеста и фильтрации старых пропусков. Отдельно проверены `..`, абсолютный компонент, разделители, управляющие символы и выход HTTPS-токена за корень при включённом пропуске.

Полный итоговый прогон: **233 passed, 1 skipped**, 37,53 с. Пропущен необязательный нативный MySQL-тест. Chrome-сценарий на искусственных данных проверил переключение с сохранением после перезагрузки, частичный результат с двумя пропусками и журнал, где эти два события остаются доступными после 510 последующих событий передачи. Проверены ширины 1440 и 390, ошибок JavaScript и горизонтального переполнения нет. Реальные клиентские файлы этим сценарием не читались.

Независимый review интерфейса завершился `ship` без материальных замечаний в пределах этой доработки. Локальная панель перезапущена после проверки пустой очереди, прежние stdout/stderr сохранены отдельными копиями. Последующий read-only контроль Chrome подтвердил включённую настройку, её блокировку при активной работе и 0 ошибок JavaScript. К этому моменту оператор уже запустил две работы; проверка их не останавливала и новых заданий не создавала. Для текущей файловой работы API подтвердил `skip_unsupported_names: true`, приватный журнал содержал четыре записи пропусков из выполненных проходов. Текущий обход ещё работал, поэтому завершение реальной копии этим контролем не подтверждено.
