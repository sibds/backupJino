# Раздельные ресурсы получения файлов, обхода и проверки

18 ноября 2026 года. Исправление устраняет удержание мест загрузки заданиями, которые заняты локальным обходом/проверкой. Оно относится к управляемой очереди и FTPS ParallelCollector.

## Подтверждённые причины

Ранее планировщик допускал до пяти обычных файловых заданий и отдельное проверяющее. До download_phase_complete даже задание с пустой очередью передач считалось обычным. Заняв все места, такие задания не давали начать файловую работу других серверов.

Кроме того, внешний ConnectionBudget.lease удерживал сеанс метаданных на всё время работы коллектора, включая локальный SHA-256 и ожидание других проверок. Свободные передатчики не означали доступность соединений. Общий слот локальной верификации также удерживался во время двух сетевых проверок источника.

Контрольный замер до изменения: 60,12 с, 1 089 984 новых байта, 17,7 КиБ/с суммарно. Новые данные были только у строки 29; пять других заданий занимались обходом и проверками. Протокол этого замера сохраняется отдельно при установке как `.state/resource-pools-speed-before.json`.

## Новая организация

| Ресурс | Ограничение в штатной конфигурации |
| --- | --- |
| Контексты файловых заданий | До 24, вместо ограничения пятью передающими заданиями |
| Контекст БД | Один, с прежним панельным допуском |
| Сетевые сеансы файлового исполнителя | Общий предел 10 сохранён |
| FTPS-сеансы метаданных | До 3 одновременно |
| FTPS-сеансы передачи данных | До 7 одновременно внутри того же общего бюджета |
| Полные обходы дерева | До 3; получение уже известного файла начинается до ожидания этого ресурса |
| Локальный SHA-256 и проверки receipt | Один общий слот |

24 — предел контекстов оркестрации, не число сетевых потоков или обещанных одновременных скачиваний. Общий исполнитель имеет 25 работников, чтобы файловые контексты не занимали место БД. Ограничение одного задания одного вида для сервера сохранено. Чисто проверяющие задания по-прежнему допускаются прежним отдельным механизмом.

Контроллер выдаёт токены по ролям. Пока есть FTPS-контексты, общий бюджет сохраняет место для метаданных: активные передатчики не могут занять все токены и затем взаимно ждать соединения для stat. Другие файловые протоколы учитываются в том же общем пределе. Для искусственно малых бюджетов тестов допускается временное заимствование метаданными доступных мест с освобождением простаивающих сеансов передатчикам. Производственная конфигурация остаётся 10/3/7.

## Сеансы метаданных

Сеанс получает токен при фактическом открытии, а не резервируется на весь срок задания. Соединение остаётся пригодным для повторного использования. При наличии ожидающих запросов пул может закрыть простаивающее соединение; занятая команда не прерывается. Учитывается небольшая задержка простоя, а при длительном ожидании — минимальный интервал использования соединения, чтобы не переподключаться на каждой команде.

Ожидающие открытия получают очередь доступа. Очистка и освобождение соединения синхронизированы: окончание коллектора и другой работник пула не могут закрыть один сеанс одновременно или дважды освободить токен. Сеанс не отзывается внутри команды или незавершённой последовательности проверки родителей пути.

При повторном открытии заново проверяются TLS и канонический корень. Корень должен совпасть с ранее подтверждённым; кеш проверенных родителей очищается. Уход за корень не разрешается ради скорости.

## Локальная работа и полнота

Получение известных недостающих объектов из постоянной очереди выполняется до ожидания слота полного обхода. Поэтому три занятых сканера не блокируют четвёртому серверу передачу уже известного файла. Потоки, ожидающие ресурса, продолжают обрабатывать pause/stop; контрольные точки и части сохраняются.

Проверки локальных receipt теперь используют тот же общий слот локального ввода-вывода, что SHA-256. Сетевые проверки источника выполняются до/после хеширования, вне этого слота. Задержка ответа FTP не занимает локального проверяющего. Проверка изменения локального файла после вычисления хеша и проверки источника перед подтверждением результата сохраняется.

Никакое окончание передачи не подменяет успешную верификацию или полноту инвентаризации. Истечение времени задания не введено. SFTP/HTTPS сохраняют прежние способы передачи; новая политика повторного использования сеансов метаданных применяется к FTPS. Общий каталог версий и retention этим изменением не добавлены.

## Проверки

Регрессии сначала воспроизвели два исходных отказа: ожидающая проверки копия занимала все места соединений; восемь серверов не могли начать работу из-за пяти занятых контекстов. Дополнительно проверены резерв метаданных, малый бюджет двух соединений, освобождение простаивающего передатчика, недопустимость прерывания занятого сеанса, согласованность корня после переоткрытия, синхронизация очистки, независимость готовой передачи от трёх занятых сканеров, единственный слот локальных receipt и отсутствие удержания этого слота во время сетевого post-check.

Протокол установки с прежними ключами, частями, ручными паузами и расписаниями — `.state/resource-pools-deployment.json`. Фактический результат следует подтверждать phase=INSTALLED, счётчиком использованных сеансов и новым минутным замером полученных байтов. Сам рост числа RUNNING не является подтверждением скачивания.
