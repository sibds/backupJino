# Папки серверов по логинам

11 ноября 2026 года пользователь потребовал заменить непонятные номера папок логинами серверов. Служебный ID нужен для журналов и идемпотентности, но не должен определять отображаемое имя папки сервера.

## Правило именования

- Основное имя: значение поля, явно сопоставленного с `login` в карте импорта. Это логин панели из записи сервера, а не FTP-логин. Для файлов и БД одной записи выбирается одна папка, даже если эти логины различаются.
- Если карта не содержит логина панели или он отсутствует, используется `ftp_login`.
- Два одинаковых имени без учёта регистра получают понятное уточнение: `<логин>--<FTP-хост>`. Неразрешимая неоднозначность останавливает операцию с `FOLDER_NAME_AMBIGUOUS`; случайные номера не добавляются.
- Недопустимые в Windows символы заменяются `_`, конечные точки и пробелы убираются, зарезервированные имена приводятся к допустимым. Совпадения проверяются после преобразования.
- Логины используются локально в именах папок по прямому запросу пользователя. Они не выводятся в публичные JSON-отчёты, документацию или логи. `Server` и `PanelSource` скрывают имя папки в `repr`.

Результирующие пути:

```text
F:\jino\<логин>\download-<ID задания>\files\
F:\jino\<логин>\panel-job-<ID задания>\databases\
```

Внутренние идентификаторы серверов и заданий сохранены. Это позволяет продолжать старые задания без нового скачивания или повторного экспорта БД. Отображаемое имя не используется как доказательство привязки аккаунта к сайту.

## Команда переноса

```powershell
.venv\Scripts\backupctl.exe backup name-server-folders --file abw_sibds__server.json --mapping examples/jino-mapping.json --destination F:\jino
```

По умолчанию выполняется dry-run без записи и авторизации. `--execute` применяет переименование. Внешний проверочный запуск дополнительно сравнил исходные файлы с сохранённой описью. Обычные `download-servers` и `export-jino-db` теперь сами используют имена по логинам; старые папки с маркерами приложения могут быть перенесены при продолжении задания.

Если целевая папка занята чужими данными либо одновременно существуют старый и новый каталоги, операция останавливается с `SERVER_FOLDER_CONFLICT`. Ничего автоматически не объединяется и не удаляется. При изменении даты, корня назначения или параметров аккаунта прежний ключ идемпотентности по-прежнему не разрешает другое задание. Исключение миграции касается только подтверждённого прежнего пути того же задания.
