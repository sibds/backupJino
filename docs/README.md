# Jino Backup Manager

**SDD 1.1 — исходная спецификация от 10 ноября 2026 года. Актуализация: 12 ноября 2026 года.**

Спецификация сервиса для разового и планового резервного копирования сайтов клиентов с Jino.ru. Основной принцип: **подключиться → получить файлы и БД → проверить → сохранить вне Jino → завершить сеанс**.

Документ предназначен разработчику или агенту разработки. Реализация должна состоять из предсказуемых программных модулей; LLM не принимает решения о действиях, способных повредить сайты или резервные копии.

Старые количества ошибок, тестов, задания и PID не являются текущим состоянием исполнителя.

Сейчас реализованы локальная панель с карточками и управляемой очередью, FTPS с 2–5 сеансами на сервер и общим пределом 10, HTTPS/SFTP-адаптеры, экспорт существующих MySQL-снимков, продолжение файлов и отдельный архивный CLI. До пяти файловых заданий в бюджете 10 сеансов и одного БД-задания одновременно (сеансы выдаёт общий ограничитель). FTPS/SFTP и БД одного сервера независимы; HTTPS-файлы и БД одного сервера последовательны. Пауза сохраняет слот. Обычные копии сохраняются в `F:\jino` по логинам; архивный каталог настраивается отдельно.

Создание нового снимка приложением, панельный экспорт в архивном `auto`, S3/Object Lock, retention, внешние уведомления и восстановление приложения остаются нереализованными. Последний полный прогон: **359 passed, 1 skipped**; детали — [39](39_ftp_performance_fixes.md). [Проверка документации и безопасный снимок интерфейса](25_documentation_review.md).

## Согласованные исходные условия

- Сайты клиентов преимущественно находятся на Jino.ru; доступ к файлам имеется по FTP, предпочтительно перейти на **FTPS или SFTP**.
- Прямого доступа к панели Jino в момент запуска может не быть. Доступа к серверу БД извне также может не быть.
- Логины и пароли **панели** хранятся в `abw_sibds__server.json` — JSON-дампе таблицы MySQL. Этот файл является основным источником для отдельного импорта учётных данных панели.
- Историческая SDD описывала `money.py` для авторизации и получения стоимости услуг. В текущей папке файла нет; собственная повторная проверка его кода не выполнялась.
- Историческое описание `sites (9).xml` указывало 43 профиля: 37 Jino и 6 иных. Этот файл отсутствует. Фактически загруженный `sites.xml` не прошёл строгий XML-разбор (строка 126, столбец 44); историческое число профилей к нему не относится. FileZilla остаётся **вторичным источником FTP-подключений**, а не источником учётных данных панели.

## Критическое ограничение

**Только FTP не обеспечивает гарантированного получения свежего SQL-дампа работающей БД.** Для полного бэкапа нужен хотя бы один дополнительный разрешённый механизм: панель Jino, подключение к БД, SSH или отдельный согласованный временный экспортёр. При его отсутствии результат `FILES_ONLY`, не `COMPLETE`.

## Приоритеты реализации

1. Первый этап: надёжный импорт и сопоставление профилей, безопасная передача файлов, зашифрованное внешнее хранение и отчёт о результате.
2. Второй этап: получение БД, предпочтительно через существующий механизм снимков Jino, с проверкой даты и полноты.
3. Третий этап: расписание, контроль восстановления, уведомления и управление портфелем сайтов.

## Решение, которое нужно подтвердить на тестовом аккаунте

Официальная документация Jino описывает ручное создание бэкапов и извлечение файлов/SQL в папку `backups/дата`, откуда их можно скачать. На одном разрешённом аккаунте наблюдены создание снимка и сквозная выгрузка SQL приложением. Стабильность API и автоматическое создание нового снимка командой приложения ещё требуют дальнейшей реализации и проверки.

## Статус спецификации

SDD описывает целевую систему; исторические сведения о вложениях не являются результатом текущей проверки. Доступен Python-прототип: [команды запуска и фактические возможности](../README.md). Структура JSON изучена без вывода значений; `sites.xml` не прошёл строгий разбор. Выполнены реальный файловый проход и отдельно разрешённый панельный пилот: [результаты](10_download_and_panel_pilot.md). Затем на одном разрешённом аккаунте приложение экспортировало и скачало все 3 БД выбранного снимка: [сквозной тест](11_database_export_integration.md). Файлы сайта и восстановление приложения этим не проверены.
