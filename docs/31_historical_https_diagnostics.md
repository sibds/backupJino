# История HTTPS отдельно от текущих ошибок

13 ноября пользователь согласовал убрать постоянно висящую метку «Файлы HTTPS · Панель хостинга не ответила корректно» из текущих предупреждений. Источник «Файлы HTTPS» формируется из сохранённого результата прежнего массового прохода; ошибки управляемых заданий имеют отдельный источник «Файлы».

displayDiagnostics исключает прежний HTTPS-результат из таблицы и её фильтра причин, в том числе для ещё ожидающих FTPS-заданий. В карточке результат остаётся как «Прежняя выгрузка HTTPS» с исторической пометкой и пояснением, что это не состояние текущего задания. Исходный код ошибки и отчёты не меняются. Журналы сохраняются; новые ошибки HTTPS/FTPS с источником «Файлы» остаются видимыми, даже если код совпадает с историческим. Даты прежней ошибки не придумываются.

Изменён только статический JavaScript: достаточно обновить страницу, перезапуск исполнителя не нужен. Проверки: сначала два регрессионных теста воспроизвели проблему; после изменения прошли оба и пять тестов графиков активности, всего 7. Проверены скрытие истории, сохранение кода, отсутствие изменения исходных данных и приоритет текущей ошибки с тем же кодом. Синтаксис JS и git diff --check проверены.
