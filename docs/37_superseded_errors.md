# Сброс прежних предупреждений после начала новой выгрузки

По запросу пользователя прежние ошибки файлов и БД перестают отображаться как текущие предупреждения, когда новое управляемое задание соответствующего типа реально начиналось (`started_at` или `first_started_at`). Правило действует и после завершения, паузы или нового отказа задания. Одна постановка в очередь без старта прежний результат не отменяет.

Источники `FTP`, `Файлы HTTPS` и прежние `Файлы` относятся к файловому заданию; `Базы данных` и прежний общий отказ `Панель` — к заданию БД. Работа файлов не отменяет ошибку БД, и наоборот. Диагностика отдельной проверки доступа `Проверка панели` сохраняет собственное значение и этим правилом не скрывается.

Текущий отказ последнего задания сохраняется, даже если его код совпадает с прежним. API дописывает диагностику управляемых заданий после результатов старого прохода; отображение выбирает последнюю совпадающую запись для текущего кода. Фильтрация одинакова для таблицы, фильтра причин и карточки. Прежнее сообщение правого блока также скрывается, когда соответствующая диагностическая запись уже отменена новым запуском.

Изменено только отображение статического JavaScript. Журналы, исходные отчёты, результаты заданий и API не очищаются и не меняются; пропуски не превращаются в полный успешный результат. Перезапуск исполнителя, новые входы в Jino и повторный запуск выгрузок не требуются. Для уже открытой страницы нужно обновление.

Проверки: **18 JS-тестов прошли**, включая графики активности, старый/новый одинаковый код, разделение файлов и БД, ожидание без старта, завершение и новую ошибку TLS. Полный Python-прогон не повторялся: Python-код не изменён.

Синтетический Chrome проверил таблицу и правый блок на ширинах 1440/1000/800/390: прежнее предупреждение скрыто, новое с тем же кодом показано, ошибок JavaScript нет. Запросы к Jino и изменения через API не отправлялись. Работающая панель отдаёт обновлённый `/assets/app.js` с `Cache-Control: no-store`; исполнитель не перезапускался. При контрольном чтении три файловых задания продолжали работу.
