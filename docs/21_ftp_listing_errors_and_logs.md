# Ошибки списка FTP и диагностика каталогов

12 ноября 2026 года пользователь сообщил текущую ошибку списка FTP и указал на отсутствие причины в журнале.

## Установленные факты

Файловое задание исходной строки 1 остановилось с `REMOTE_LIST_UNSUPPORTED` на этапе `SCANNING` после 3 857 каталогов, при 0 полученных байтов. Строка 38 продолжала обход. Это текущий сбой, а не [историческое предупреждение TLS](20_historical_ftp_diagnostics.md).

Обработчик `except (ValueError, ftplib.error_perm)` объединял ошибки разбора и все постоянные отказы FTP. Сюда попадал и `UnicodeDecodeError`, подкласс `ValueError`. Числовой ответ, операция и путь не сохранялись. **Точную причину прежнего отказа восстановить по журналу нельзя.** Уже прочитанные тысячи каталогов не позволяют считать общей причиной отсутствие поддержки списка на сервере.

## Исправление

| Наблюдение | Результат |
| --- | --- |
| `500`, `502`, `504` при `MLSD` | `REMOTE_LIST_UNSUPPORTED` |
| `550` при переходе или чтении каталога | `REMOTE_DIRECTORY_UNAVAILABLE`: нет доступа либо каталог недоступен; один код не различает причины |
| `530`, `532` | `FTP_LOGIN_DENIED` |
| Другой постоянный отказ | `FTP_LIST_REJECTED` |
| Некорректные факты списка | `REMOTE_LIST_INVALID` |
| Имена не декодируются в UTF-8 | `REMOTE_LIST_ENCODING_INVALID`; автоматической подмены кодировки нет |
| Временный отказ, EOF, сетевой обрыв | `TRANSFER_INTERRUPTED`, прежние пять переподключений |

Сохраняются безопасное имя операции и числовой FTP-код, если он был получен. При переходе различаются `CWD` и проверка `PWD`. TLS, проверка корня и ограничения ссылок сохранены. Неподдерживаемая команда и повреждённый список не превращаются в пустой каталог.

Перед чтением каждого каталога пишется `SCANNING` с полем `directory`; при ошибке — `DIRECTORY_ERROR`, путь, код приложения, `operation` и доступный `ftp_reply_code`. Это приватные данные локальной панели. Произвольный текст ответа, пароли и cookies не сохраняются. Разрешены фиксированные операции и числовые ответы 100–599. При сетевом тайм-ауте ответа FTP может не быть.

В карточке сервера поля подписаны отдельно. Фильтр **«Ошибки каталогов»** выбирает `DIRECTORY_ERROR` до `LIMIT 500`, поэтому последующие чтения не вытесняют причину из этого фильтра. Полная история остаётся в SQLite; интерфейс ограничен последними 500 событиями выбранного типа.

Управляемый файловый режим уже использует `continue_on_error=True`. Теперь отказ `550` отдельного подкаталога позволяет продолжить доступные файлы. Каталог и детали отказа попадают в `files.errors`, результат — `PARTIAL`. Неизвестное содержимое не включается в подтверждённый общий объём. Отказ разрешённого корня и строгий режим остаются фатальными. Поведение не означает, что прежний реальный сбой был именно `550`; ошибки структуры, кодировки, авторизации и TLS не пропускаются как отказ доступа.

## Проверки и применение

- Синтетические проверки сначала воспроизвели потерю деталей и неверную классификацию. Итоговый полный прогон: **262 passed, 1 skipped**, 43,68 с; пропущен необязательный нативный MySQL-тест. Команда: `.venv/Scripts/python.exe -m pytest -q --basetemp .test-tmp/ftp-listing-release`.
- Покрыты FTP-коды, некорректные факты, UTF-8, строгий режим, отказ корня, доступные файлы при отказе подкаталога, безопасные поля журнала и сохранение ошибки в отдельном фильтре после 510 последующих событий.
- Chrome на искусственных данных при 1440/390 px: видны фильтр, путь, операция `MLSD` и ответ `550`; ошибок JavaScript и горизонтального переполнения нет. Это пример, а не ответ реального Jino. Узкий финальный review вернул `ship` для отображения этих полей.
- Для установки Python-кода корректно остановлен исполнитель, прежние журналы скопированы, приложение перезапущено. Продолжены **те же два задания** строк 1 и 38. Новых заданий, SQL-экспортов и удалений не было. Подтверждённые части сохранены. Обход строки 38 начался заново: прежняя инвентаризация была только в памяти.
- После установки оба задания имели `RUNNING / SCANNING`; журнал уже фиксирует реально запрашиваемые каталоги. Прежняя причина ещё не воспроизведена. Завершение выгрузки, полный бэкап и восстановление сайта не заявляются.
