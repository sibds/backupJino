# Отказ из-за имени каталога, несовместимого с Windows

После этой диагностики пользователь разрешил пропуски: реализованный режим описан в [следующей доработке](18_skip_unsupported_names.md). Ниже сохранён первоначальный результат исследования.

11 ноября 2026 года пользователь сообщил сообщение «Файлы · Обнаружен путь за разрешённым корнем или недопустимое имя».

## Проверка фактического отказа

Из SQLite управляемой очереди прочитано последнее файловое задание с `REMOTE_PATH_UNSAFE`. Оно использовало FTPS и завершилось на этапе `SCANNING`; последняя сохранённая отметка — 41 обследованный каталог. На момент исследования выполняющихся заданий не было.

Повторён только предварительный обход того же FTP-корня, с учётом текущей привязки сервера и блокировки аккаунта. Авторизация выполнялась через исправленный FTPS-адаптер с проверкой сертификата и имени. Новая резервная работа не создавалась, файлы не скачивались и не изменялись.

На 42-м каталоге, после просмотра 2 755 записей, воспроизведён отказ `safe_name`. Причина — **двоеточие `:` в имени вложенного каталога**. В данном имени нет `..`, разделителей пути, управляющих символов, конечной точки или пробела; оно не является зарезервированным Windows-именем. Этот конкретный отказ вызван несовместимостью имени с Windows.

## Почему сообщение выглядит как ошибка границ доступа

Текущая функция `safe_name` одним кодом `REMOTE_PATH_UNSAFE` обозначает и недопустимые компоненты пути, и имена, которые нельзя сохранить обычным способом в Windows. Поэтому общая подпись недостаточно точно объясняет этот случай. Linux допускает двоеточие в имени, Windows не позволяет создать такое имя как обычный файл или каталог.

Проверка выполняется перед скачиванием всего дерева. В этой работе она остановила предварительный обход; наличие успешного FTPS-входа не означает завершения файловой копии.

## Граница текущего поведения

Автоматическое обратимое преобразование несовместимых имён пока не реализовано. Для поддержки таких каталогов потребуется явное отображение исходного удалённого пути в локальный, сохранение исходного имени в манифесте и проверка коллизий при повторе и восстановлении. Простая замена всех двоеточий на подчёркивания может объединить разные исходные имена. Пропуск каталога должен явно оставлять результат частичным; молчаливый пропуск или ослабление проверки корня неприемлемы.

В ходе этой диагностики реализация, настройки сервера и состояние задания не менялись. Это установленная причина, а не отчёт об исправлении.

Точный клиентский путь сохранён только локально в `.state/unsafe-path-diagnostic.json`. Он намеренно не включён в документацию и вывод терминала. Диагностические команды этой рабочей папки: `.state/unsafe_path_inspect.py` (чтение метаданных задания) и `.state/unsafe_path_probe.py` (разрешённый сетевой обход только для чтения). Повторный обход не является частью pytest.
