# Предупреждение для дампа без объектов БД

Завершённый небольшой SQL, содержащий только известные настройки сеанса, получает `SQL_NO_OBJECTS`, а не `DB_INTEGRITY_FAILED`. Выгрузка следующих БД продолжается; предупреждение сохраняется в артефакте, результате, манифесте, журнале и карточке БД. Оно означает отсутствие объектов **в дампе**, а не доказанное отсутствие таблиц в исходной БД. Оператору предлагается проверить, ожидается ли пустая база.

Распознавание ограничено 64 КиБ и проверяет весь файл: семь обязательных пар сохранения/восстановления настроек, конечный маркер SQL_NOTES и разрешённые SET. UNIQUE_CHECKS может отсутствовать только с обеих сторон. Разрешена известная директива sandbox MariaDB. Неизвестные команды, HTML, явные сообщения об ошибке и незавершённая оболочка этим исключением не принимаются. Прежние проверки размера, SHA-256, привязки и существующих форматов SQL сохранены.

Для настоящего `DB_INTEGRITY_FAILED` остаются повторное скачивание и сохранение повреждённой версии до проверенной замены — [43](43_database_integrity_redownload.md). Предупреждение не запускает повтор и не превращает DB_ONLY в полный бэкап или успешный тест восстановления.

Регрессии проверяют предупреждение, продолжение следующей БД, отклонение повреждённых вариантов и замену предупреждения при появлении новой обычной копии. Отдельно выполнена локальная проверка ранее сохранённого файла, без входа в Jino.

Проверки: **415 passed, 1 skipped**, **22 JS-теста**. Исправление установлено; восстановлены пять активных файловых заданий и 26 ожидающих с прежними ID, порядком и датами. Попытка локально завершить всё задание остановлена проверкой полноты: исходный список содержит ещё не обработанные БД. Сохранённые части не изменены. Следующий штатный проход принимает этот дамп с предупреждением и продолжает список. Протокол — `.state/empty-sql-warning-deployment.json`.
