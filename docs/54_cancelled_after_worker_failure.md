# CANCELLED после сбоя параллельной загрузки

16 ноября обнаружено девять файловых заданий в WAITING_OPERATOR с CANCELLED. Синтетический тест подтвердил причину: после исходной ошибки работника общий сигнал прекращения вызывал CANCELLED в последующей сверке конфликтов, скрывая исходный код. Это препятствовало штатному автоматическому продолжению сетевого сбоя.

В ParallelCollector исходная ошибка теперь передаётся до сверки конфликтов. Проверки параллельных передач и локальной верификации: **22 passed**.

Через штатное действие retry работающей панели возвращены в очередь девять прежних заданий строк 2, 4, 5, 10, 18, 27, 29, 32, 38. Ключи сверены, части не удалялись. Контрольное чтение: нет WAITING_OPERATOR с CANCELLED; девять заданий QUEUED, семь других заданий RUNNING (шесть файловых и одно БД).

Исполнитель ради установки исправления не перезапускался по указанию пользователя. Исправление кода подготовлено для следующего запуска; до применения повторение дефекта возможно. История событий сохранена.
