# Продолжение БД после тайм-аута

По указанию оператора от 16 ноября истечение времени не завершает начатую управляемую выгрузку файлов или БД окончательно.

У файлов общий предел уже снят (документ 50). Для БД `EXPORT_TIMEOUT`, `DB_EXPORT_TIMEOUT`, `OPERATION_TIMEOUT`, `TRANSFER_TIMEOUT` и `LOW_SPEED_TIMEOUT` теперь возвращают то же задание в расписание без ограничения возраста и числа повторов. Задержки — 5, 15, затем 60 минут; общий допуск входов панели сохраняется. Счётчик тайм-аутов независим от повторов повреждённого дампа. Сохраняются ключ, журнал экспорта, части и исходное время начала; повтор сверяет фактический результат предыдущей операции штатным workflow.

Тайм-аут отдельного зависшего запроса остаётся механизмом освобождения соединения. Ручные пауза, остановка, «Пропустить», блокировка сервера и смена привязки не отменяются автоматически. Проверки TLS, целостности и безопасных путей сохранены.

Целевые проверки БД и запросов оператору: **33 passed**, включая восемь последовательных тайм-аутов каждого из пяти видов у задания старше суток с неизменным ключом.

Изменение backend подготовлено; в уже запущенный процесс без перезапуска оно не загружается. Действующие скачивания ради установки этого изменения не останавливались.
